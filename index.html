01 / Overview

这是一个什么游戏

《重生之满级暴击》是基于 LibGDX 1.12.1 (Java) 从零搭建的原创 2D 肉鸽割草游戏，由「云麓盒子」开发。它脱离任何既有玩法，自建世界观、数值、美术与养成体系：摇杆走位、自动锁敌、升级三选一、波次刷怪与 BOSS Rush，全部围绕「暴击」这一条主轴设计。业务逻辑写在平台无关的 core 模块，Android 与 Windows 复用同一份代码。

02 / How it works

原理说明

这一节回答三个问题：伤害凭什么这样算、重生为什么会变强、以及一局游戏是怎么跑起来的。所有数值与类名都对应仓库里的真实实现，不是概念示意。

2.1 · DamageCalculator.java

满级暴击乘区：伤害不是加法，是分层相乘

核心思路是把每一类加成拆成独立乘区，而不是堆在一个加法池里。这样数值不会互相稀释，也让「暴击」成为可以单独调参、单独触发特效的维度。

// battle/damage/DamageCalculator.java —— 最终伤害
最终伤害 = 基础攻击
         × 流派倍率 × 神装套装系数 × 符文增幅 × 回溯印记加成 × 天赋/局内被动
         × 暴击判定系数 × 满级超额暴击系数

// 暴击判定
isCrit = roll(0..100) < (暴击率 − 目标暴击抗性)

// 暴击回溯：每次暴击命中都返还资源，形成正反馈
暴击命中 → 回血 = 基础攻击 × 2% ，主动技能 CD − 0.15s

// 满级暴击：双阈值同时满足，才额外触发范围冲击波
if (暴击率 ≥ 85% && 爆伤加成 ≥ 150%)
    暴击命中附带范围冲击波（2.5× 伤害）
暴击率阈值OVER_CRIT_CRIT_RATE = 85%
爆伤阈值OVER_CRIT_DAMAGE_BONUS = 150%
冲击波倍率2.5 ×
回溯回血2% / 次
为什么用「且」而不是「或」？ 单堆暴击率或单堆爆伤都能靠单一装备毕业；双阈值逼迫玩家在流派、神装、符文、天赋四条养成线之间做取舍，这正是肉鸽构筑的深度来源。阈值常量集中在 DamageCalculator，方便整体调平衡而不改公式结构。
2.2 · MetaProgress.java

回溯印记：把「失败」也变成收益

每局结束——无论通关或失败——都发放回溯印记。每枚永久提供 +1.5% 暴击率 / +4% 爆伤，写入带 CRC 校验的存档 save/maxcrit_save.json。

于是「重生」不是惩罚而是货币：局内死得越早，下一局的起手面板仍比上一局更高。这个闭环把单局随机性，兑换成了跨局的确定性成长。

2.3 · 养成闭环

四条线，共用一套面板预计算

系统作用落点
回溯印记暴击率 / 爆伤永久加成SaveManager.echoMarks
神装 6 部位2 / 4 / 6 件激活裂隙·虚空·破晓套装weapon…ring
暴击符文每枚 +1.5% 暴击率、+5% 爆伤SaveManager.runes
觉醒天赋树瞬杀 / 永续 / 神佑 三系 9 节点天赋点前置解锁

进局前把局外属性一次性合并进战斗面板，局内不再反复回查存档，避免每帧 IO 与乘区漂移。

2.4 · BattleWorld / WaveManager

一局是怎么跑起来的

自动武器按「距离优先 + 视野检测」锁敌，玩家只需要走位；数值成长交给三选一构筑；难度膨胀交给波次计时器。

STEP 01

摇杆走位

虚拟摇杆 / WASD，圆形碰撞体，拉扯怪群。

STEP 02

自动锁敌

距离优先扫描，自动发射，子弹走对象池。

STEP 03

经验球

击杀掉落，磁铁类技能扩大拾取半径。

STEP 04

三选一

经验满暂停，按稀有度权重抽技能，可叠加进阶。

STEP 05

波次推进

小怪 → 精英 → BOSS，计时器持续抬血量与抗性。

STEP 06

结算重生

BOSS 掉暴击突破晶，发放回溯印记，回到局外。

性能约束是设计的一部分：子弹、怪物、经验球、特效、召唤物全部强制 Pool<T>，禁止频繁 new；SpriteBatch 合批；屏幕外怪物休眠；技能与怪物数值全部 JSON 驱动，不硬编码。

2.6 · 工程纪要

一次真实的启动闪退根因修复

真机崩溃栈指向 NoClassDefFoundError: com/badlogic/gdx/utils/SharedLibraryLoader。原因不是代码写错，而是 依赖解析方式：

// LibGDX 1.12.0 起把该类拆到独立 artifact
// 但工程用 files(...) 直连，无传递依赖能力
api files('../libs/gdx-1.12.1.jar')

GdxNativesLoader.load()
  → new SharedLibraryLoader()  // MISSING
  → AndroidApplication.initialize() 中断
  → input 为 null → onResume() NPE → 闪退

修复不靠下载（Maven 全通道实测不可达）：在 core/src/.../gdx/utils/ 下自建等价类，内联平台判定、去掉 jnigen-commons 依赖，Android 分支直接 System.loadLibrary。4 个 jar/aar 共 1290 个引用的完整性扫描确认：只缺这 1 个类。

03 / Asset pipeline

素材怎么变成游戏资源

仓库根目录里那些以 sucai 开头的目录，是同一批原始美术在不同处理阶段的产物；真正进包的是 assets/。

sucai/ 121 张源图：95 张 2848×1600 UI 成品稿 + 26 张 2048×2048 图标/立绘/场景 │ ├─ sucai_split/ / sucai_parts/ / sucai_parts_selected/ 切图与零件筛选中间产物 ├─ sucai_ui/ UI 底板整理结果 │ ▼ tools/build_assets.py 切图 / 缩放 / 生成中文位图字体 assets/ ├── textures/ui/ 79 张 1280×720 JPG（图做背景，数值与按钮由 Scene2D 动态绘制） ├── textures/icons/ 41 个 512px PNG8 图标 / 立绘 / 特效 ├── ui/font/ deskhan.fnt + deskhan.png（中文 BitmapFont，覆盖项目全部用字） ├── config/ skill.json / monster.json / equip.json / talent.json └── sound/ *.wav → Gdx.audio.newSound（可并发叠加）；*.ogg → newMusic（长循环）
「底板 + 动态数据层」是关键取舍：UI 成品稿里已经含中文文案，但它只当背景图用；血条、数值、列表、按钮全部用 Scene2D 实时绘制，否则每次数值变化都要重新出图。音效的 .wav / .ogg 之分也不是习惯，而是 GameAssets.loadSounds() 按扩展名硬分流到 SoundPool 或 MediaPlayer 的约束。
